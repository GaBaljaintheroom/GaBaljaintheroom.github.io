## ITS(Intelligent Transport Systems)

- 교통의 효율성과 안전성을 높이는 지능형 교통체계
- 교통수단과 교통시설에 첨단 기술을 접목해 운영과 관리를 지원
- 예시 : 교통카드 환승, 하이패스, 내비게이션, 대중교통 실시간 위치 정보 등

## C-ITS(Cooperative Intelligent Transport Systems)

- 차량, 도로 인프라, 보행자 단말이 서로 정보를 공유하는 협력형 교통체계

| 단계 | 기존 ITS (센터 중심) | C-ITS (참여자 간 협력) |
| --- | --- | --- |
| 수집 | 도로 검지기, CCTV, 차량 위치 자료 | 차량과 인프라가 자신의 상태를 직접 감지 |
| 운영 | 센터가 정보를 모아 분석 및 관제 | V2X로 주변 개체와 직접 정보 교환 |
| 활용 | 교통정보 안내, 신호 운영에 반영 | 급정거 등 위험에 각 개체가 즉시 대응 |

- 기존 ITS는 정보가 센터를 거쳐 전달되므로 반영이 느린 반면, C-ITS는 개체 간 직접 통신으로 100ms 수준의 짧은 지연 안에 위험을 전달할 수 있음

## V2X 이란

V2X(Vehicle-to-Everything)는 **차량이 주변의 모든 것(다른 차량, 도로 인프라, 보행자, 네트워크 등)과 무선으로 정보를 주고받는 통신 기술**이다.

자율주행차는 카메라, 라이다, 레이더 같은 센서로 주변을 인식하지만, 센서는 **시야(Line-of-Sight)** 에 의존하기 때문에 한계가 있다.

- 앞의 대형 트럭에 가려진 전방 차량의 급정거
- 건물에 가려진 교차로 너머에서 달려오는 차량
- 아직 보이지 않는 신호등의 남은 시간
- 수 km 앞의 사고나 공사 구간

V2X는 이런 정보를 **무선 통신으로 미리 전달**받아 센서의 한계를 보완한다. 그래서 V2X를 "보이지 않는 곳을 보는 센서"라고 부르기도 한다.
V2X는 통신 대상에 따라 크게 V2V, V2I, V2P, V2N으로 나뉜다.

```
                 ┌──────────┐
                 │ Network  │  (V2N)
                 │ (Cloud)  │
                 └────▲─────┘
                      │
┌──────────┐     ┌────┴─────┐     ┌──────────┐
│ Vehicle  │◄───►│ Vehicle  │◄───►│   RSU    │
│          │ V2V │  (OBU)   │ V2I │ (신호등)  │
└──────────┘     └────┬─────┘     └──────────┘
                      │
                      ▼  (V2P)
                 ┌──────────┐
                 │Pedestrian│
                 └──────────┘
```

### V2V

V2V(Vehicle-to-Vehicle)는 **차량과 차량 간의 직접 통신**이다.

각 차량은 자신의 위치, 속도, 방향, 가속도, 브레이크 상태 등을 초당 약 10회 주변에 브로드캐스트하고, 주변 차량은 이 정보를 받아 충돌 위험을 판단한다.

- 전방 추돌 경고(FCW, Forward Collision Warning)
- 교차로 충돌 경고(IMA, Intersection Movement Assist)
- 비상 전자 브레이크등(EEBL, Emergency Electronic Brake Light) : 앞앞 차량의 급제동 알림
- 사각지대 / 차선 변경 경고(BSW/LCW)
- 군집 주행(Platooning)

기지국 등 인프라를 거치지 않고 차량끼리 직접 통신하기 때문에 **지연 시간이 짧은 것**이 핵심이다.

### V2I

V2I(Vehicle-to-Infrastructure)는 **차량과 도로 인프라(신호등, 노변 장치 RSU 등) 간의 통신**이다.

- 신호 정보 제공(SPaT, Signal Phase and Timing) : 현재 신호와 남은 시간
- 교차로 지도 정보(MAP) : 차선 구조, 정지선 위치
- 도로 위험 정보(TIM, Traveler Information Message) : 공사, 사고, 노면 상태
- 신호 위반 경고, 감속 구간 안내
- 긴급 차량 신호 우선 처리

우리나라의 **C-ITS(Cooperative Intelligent Transport Systems, 차세대 지능형 교통 시스템)** 사업이 대표적인 V2I 활용 사례다.

### V2P

V2P(Vehicle-to-Pedestrian)는 **차량과 보행자(스마트폰, 웨어러블 기기 등) 간의 통신**이다.

- 횡단보도 보행자 접근 경고
- 건물이나 주차 차량에 가려진 보행자 / 자전거 / 킥보드 탑승자 감지

보행자는 단말 배터리와 장비 보급 문제가 있어 V2V, V2I보다 상용화 속도는 느린 편이다. 대신 RSU에 설치된 카메라/센서가 보행자를 감지해 차량에 알려주는 방식(V2I 기반)도 함께 활용된다.

### V2N

V2N(Vehicle-to-Network)은 **차량이 이동통신망(LTE/5G 기지국)을 통해 클라우드나 서버와 통신**하는 방식이다.

- 실시간 교통 정보, 정밀 지도(HD Map) 업데이트
- 원격 진단, OTA(Over-The-Air) 소프트웨어 업데이트
- 광역 위험 정보 제공

V2V, V2I처럼 근거리 직접 통신이 아니라 기지국을 거치기 때문에 지연 시간은 상대적으로 길지만, **넓은 범위의 정보**를 받을 수 있다.

### OBU

OBU(On-Board Unit)는 **차량에 탑재되는 V2X 통신 단말기**다.

- 차량의 CAN 버스, GPS 등에서 위치/속도/브레이크 상태 등을 수집해 BSM 같은 메시지를 생성하고 브로드캐스트한다.
- 주변 차량이나 RSU로부터 메시지를 수신하고, 서명을 검증한 뒤 위험 상황을 판단해 운전자(또는 자율주행 시스템)에게 경고한다.
- 메시지 서명/검증을 위한 인증서와 개인키를 안전하게 보관해야 하므로 **HSM(Hardware Security Module)** 이나 보안 칩을 함께 사용하는 경우가 많다.

공장에서 차량에 내장되는 형태와, 기존 차량에 추가로 장착하는 애프터마켓 형태(ASD, Aftermarket Safety Device)가 있다.

### RSU

RSU(Roadside Unit)는 **도로변(교차로, 신호등, 갠트리 등)에 설치되는 V2X 통신 장치**다.

- 신호 제어기와 연동해 SPaT, MAP 메시지를 브로드캐스트한다.
- 도로 위험 정보, 공사/사고 정보를 차량에 전달한다.
- 차량으로부터 수신한 정보를 교통 관제 센터로 전달한다. (백홀망 연결)
- 차량에 인증서 갱신, CRL(인증서 폐기 목록) 등을 중계하는 역할을 하기도 한다.

OBU가 "차량의 V2X 단말"이라면, RSU는 "도로의 V2X 단말"이라고 생각하면 된다.

### BSM

BSM(Basic Safety Message)은 미국 SAE J2735 표준에 정의된 **V2V 안전 서비스의 핵심 메시지**다.
차량은 BSM을 일반적으로 **초당 10회(100ms 주기)** 브로드캐스트하며, 메시지는 ASN.1로 정의되고 UPER로 인코딩된다.
(유럽 ETSI 표준에서는 비슷한 역할을 하는 메시지를 CAM, Cooperative Awareness Message라고 부른다.)

BSM은 크게 두 부분으로 구성된다.

**Part I - Core Data (필수)**

| 필드 | 설명 |
| --- | --- |
| msgCnt | 메시지 순번 (0~127) |
| id | 임시 ID (4바이트), 프라이버시 보호를 위해 주기적으로 변경 |
| secMark | 분 단위 내 밀리초 시각 |
| lat / long / elev | 위도, 경도, 고도 |
| accuracy | 위치 정확도 |
| transmission | 변속기 상태 (주행, 후진, 중립 등) |
| speed / heading | 속도, 진행 방향 |
| angle | 조향각 |
| accelSet | 4축 가속도 (종/횡/수직 가속도, 요 레이트) |
| brakes | 브레이크 상태 (ABS, 트랙션 컨트롤 등 포함) |
| size | 차량 폭, 길이 |

**Part II - 확장 데이터 (선택)**

- 차량 이벤트 플래그 (비상등, 급제동, 에어백 전개 등)
- 경로 이력(Path History), 경로 예측(Path Prediction)
- 긴급 차량 정보, 날씨 정보 등

BSM은 그대로 전송되지 않고, IEEE 1609.2로 **서명된 뒤** 전송된다. 수신 측은 서명을 검증해 메시지가 신뢰할 수 있는 차량에서 보낸 것인지, 위변조되지 않았는지 확인한다.
또한 위치를 계속 브로드캐스트하기 때문에 추적 위험이 있어, 임시 ID와 서명용 가명 인증서를 주기적으로 함께 변경한다.

### WAVE

WAVE(Wireless Access in Vehicular Environments)는 **IEEE 802.11p 기반의 차량 통신 기술**이다. Wi-Fi 계열 기술을 차량 환경에 맞게 수정한 것으로, DSRC(Dedicated Short Range Communications)라고도 부른다.

> **DSRC와 WAVE는 같은 것일까?**
>
> 엄밀히는 다르다. DSRC는 "차량용 근거리 전용 통신"이라는 **분류 이름**이고, WAVE는 IEEE가 만든 **구체적인 프로토콜 스택**(802.11p + IEEE 1609)이다.
> 미국은 1999년 FCC가 5.9GHz 대역을 DSRC용으로 배정했고, 이 대역에서 사용하는 표준이 WAVE이기 때문에 미국 V2X 맥락에서는 **DSRC ≈ WAVE**로 섞어 부른다.
>
> 반면 한국, 일본, 유럽에서 DSRC는 **5.8GHz 요금 징수(톨링)용 통신**을 가리키는 경우가 많다. 우리나라 하이패스, 일본 ETC, 유럽 CEN DSRC가 여기에 해당하며, 이는 WAVE와 호환되지 않는 별개의 기술이다.
>
> | 구분 | WAVE (미국식 DSRC) | 톨링용 DSRC |
> | --- | --- | --- |
> | 주파수 | 5.9GHz | 5.8GHz |
> | 기반 기술 | Wi-Fi (802.11p) | 지역별 독자 규격 |
> | 용도 | V2V, V2I 안전 서비스 | 고속도로 요금 징수 |
> | 통신 형태 | 주변에 브로드캐스트 | 차량과 요금소 간 1:1 |
> | 통신 거리 | 수백 m | 수~수십 m |
> | 사례 | 미국 DSRC 시범사업 | 한국 하이패스, 일본 ETC, 유럽 CEN DSRC |
>
> 따라서 국내 자료에서 "DSRC"가 나오면 V2X용 WAVE인지, 하이패스 같은 톨링 기술인지 문맥으로 구분해야 한다.

WAVE는 하위 계층인 IEEE 802.11p와 상위 계층인 IEEE 1609 표준군으로 구성된다.

```
┌─────────────────────────────────────────┐
│     Application (SAE J2735 BSM 등)      │
├─────────────────────┬───────────────────┤
│  WSMP (IEEE 1609.3) │    IPv6 / UDP     │
├─────────────────────┴───────────────────┤
│        Security (IEEE 1609.2)           │
├─────────────────────────────────────────┤
│  Multi-channel Operation (IEEE 1609.4)  │
├─────────────────────────────────────────┤
│        MAC / PHY (IEEE 802.11p)         │
└─────────────────────────────────────────┘
```

| 표준 | 내용 |
| --- | --- |
| IEEE 802.11p | 물리/MAC 계층. 5.9GHz 대역, 10MHz 채널 사용. 별도의 연결(Association) 과정 없이 바로 통신 (OCB 모드) |
| IEEE 1609.2 | 보안 서비스 (서명, 암호화, 인증서 형식) |
| IEEE 1609.3 | 네트워크 서비스, WSMP(WAVE Short Message Protocol) |
| IEEE 1609.4 | 다중 채널 운용 (제어 채널 CCH / 서비스 채널 SCH 전환) |

일반 Wi-Fi는 AP에 접속(인증, 연결)하는 과정이 필요하지만, 고속으로 움직이는 차량은 그럴 시간이 없다. 그래서 802.11p는 연결 과정 없이 즉시 브로드캐스트할 수 있도록 설계되었다.
또한 IP 계층은 헤더가 크기 때문에, 안전 메시지는 가볍고 빠른 **WSMP**를 사용한다.

WAVE는 오랜 기간 검증된 기술이지만, 미국 FCC가 2020년 5.9GHz 대역을 재편하면서 ITS 대역을 C-V2X에 할당했고, 우리나라도 2023년 말 C-ITS 통신 방식을 **LTE-V2X 단일 표준**으로 결정하면서 점차 C-V2X로 무게중심이 옮겨가고 있다. (유럽은 802.11p 기반의 ITS-G5를 사용 중이다.)

### C-V2X

C-V2X(Cellular V2X)는 **3GPP에서 표준화한 이동통신(LTE/5G) 기반의 V2X 기술**이다.

| 구분 | 3GPP 릴리즈 | 특징 |
| --- | --- | --- |
| LTE-V2X | Release 14 (2017) | 기본 안전 서비스 (BSM 등) |
| LTE-V2X 개선 | Release 15 | 반송파 집성, 고차 변조 등 성능 개선 |
| NR-V2X (5G-V2X) | Release 16 (2020) | 군집 주행, 센서 공유, 원격 주행 등 고도화 서비스 |

C-V2X는 두 가지 통신 인터페이스를 가진다.

- **PC5 (Sidelink, 직접 통신)** : 기지국을 거치지 않고 단말 간 직접 통신. V2V, V2I, V2P에 사용된다. 이동통신 가입이나 기지국 커버리지가 없어도 동작한다.
- **Uu (네트워크 통신)** : 기지국을 거쳐 서버와 통신. V2N에 사용된다.

PC5 직접 통신의 자원 할당 방식도 두 가지가 있다.

- **Mode 3 (NR에서는 Mode 1)** : 기지국이 무선 자원을 스케줄링
- **Mode 4 (NR에서는 Mode 2)** : 단말이 주변 채널을 센싱해 스스로 자원을 선택 (기지국 없이 동작, 안전 서비스에서 주로 사용)

### WAVE vs C-V2X

| 구분 | WAVE (DSRC) | C-V2X (LTE-V2X) |
| --- | --- | --- |
| 표준 단체 | IEEE | 3GPP |
| 기반 기술 | Wi-Fi (802.11p) | LTE / 5G |
| 채널 접근 | CSMA/CA (경쟁 기반) | SPS (센싱 기반 반지속적 스케줄링) |
| 통신 범위/신뢰성 | 상대적으로 짧음 | 상대적으로 김 (코딩 이득 등) |
| 네트워크 연동 | 별도 구축 필요 | 기존 이동통신망 활용 가능 (Uu) |
| 진화 경로 | 802.11bd (NGV) | NR-V2X (5G) |

중요한 점은 **통신 방식(하위 계층)이 달라도 상위 계층은 공유한다**는 것이다.
미국 기준으로 C-V2X를 사용하더라도 메시지는 SAE J2735(BSM 등), 보안은 IEEE 1609.2, 인증서 관리는 IEEE 1609.2.1(SCMS)을 그대로 사용한다.
즉, 무선 기술이 WAVE에서 C-V2X로 바뀌더라도 ASN.1로 정의된 메시지와 보안 계층에 대한 이해는 그대로 유효하다.


### C-ITS 기반 기술

**위치와 시간**

- 위치 : GNSS(Global Navigation Satellite System, 위성항법시스템 총칭) 위치를 HD Map(High Definition Map, 고정밀 지도)과 연결해, 수신한 위험이 같은 차선이나 같은 교차로의 위험인지 판단
- 시간 : 단말 간 시각을 동기화해 메시지 생성 시각을 비교하고, 오래된 정보는 사용하지 않도록 제한

**아키텍처와 메시지**

- ITS 스테이션 아키텍처
  - 차량, 인프라, 보행자 단말의 정보 처리와 통신 기능을 계층으로 구성
  - 관리와 보안 기능을 포함한 공통 구조를 정의해 상호 운용이 가능한 설계를 지원
- 표준 메시지
  - 차량 상태와 이벤트 정보를 공통 데이터 형식으로 교환
  - 북미 : BSM, SPaT, MAP / 유럽 : CAM, DENM
- 제조사가 달라도 같은 프로파일과 규격을 선택해야 서로 통신할 수 있음

**PKI와 인증서**

- PKI(Public Key Infrastructure, 공개키 기반 구조)
  - 인증서를 발급하고 관리하는 인증 인프라
  - V2X에서는 미국의 SCMS(Security Credential Management System), 유럽의 CCMS(C-ITS Credential Management System) 등이 해당
- 인증서(Certificate)
  - 공개키, 발급자, 유효기간, 허용 권한을 담은 전자 증명서
- CA(Certificate Authority)와 인증서 체인
  - CA : 인증서를 발급하는 기관
  - 인증서를 검증할 때는 발급한 상위 CA의 인증서를 따라 올라가 신뢰하는 Root CA까지 확인함
  - 이 체인을 통해 단말의 공개키와 권한에 대한 신뢰가 연결됨
- 개인키와 공개키
  - 개인키는 단말이 안전하게 보관하고, 짝이 되는 공개키는 인증서에 담아 상대에게 제공
  - 송신 측은 개인키로 서명하고, 수신 측은 인증서의 공개키로 서명을 검증함

**표준 : 국제 표준과 지역 적용**

- 국제 표준
  - ISO, IEEE, ITU(International Telecommunication Union, 국제전기통신연합) 등이 관련 규격을 정의해 공통 기술 기반을 제공하고 상호 운용을 지원
- 지역별 요구사항
  - 지역마다 주파수, 통신 방식, 인증 정책, 프라이버시 요구가 다름
  - 국제 표준을 기반으로 지역별 프로파일과 세부 규격을 선택해 적용
- 상호 운용의 조건
  - 같은 표준 이름뿐 아니라 버전, 옵션, 메시지, 신뢰 정책까지 일치해야 함

### CAMP와 SCMS 개요

**CAMP(Crash Avoidance Metrics Partnership)**
- 자동차 제조사들이 차량 안전과 협력 통신을 함께 연구해 온 협력체
- USDOT(미국 교통부)와 함께 SCMS PoC(Proof of Concept) 개발에 참여

**SCMS PoC의 목적**
- 대규모 V2V, V2I 통신에서 인증과 프라이버시를 함께 지원하는 설계를 검증
- 인증서 발급, 관리와 신뢰 운영에 필요한 개념, 구조, 인터페이스를 정립

**SCMS PoC 이후**
- 2018년 PoC가 종료되었고, 핵심 설계 개념은 이후 구현과 IEEE 1609.2.1 표준에 반영됨

### IEEE 1609.2

- 보호 대상
  - V2X 응용 메시지와 관리 메시지의 보안 형식 및 처리 방법을 정의
- 보안 기능
  - 메시지 서명/검증과 암호화, 디지털 인증서 형식, 보안 데이터 형식
  - 인증서와 권한 정보를 사용해 메시지의 출처와 무결성을 확인
- 수신 처리 흐름 예시
  1. 서명, 인증서, 권한, 생성 시각을 확인
  2. 검증을 통과한 메시지만 단말 내부의 V2X 응용에 전달
  3. 응용은 상황과 메시지 내용이 타당한지 판단해 운전자 경고 등에 활용

### IEEE 1609.2.1

- 인증서 공급 및 관리
  - 단말이 인증서를 요청하고 공급받는 절차를 정의
  - 단말과 인증 인프라(SCMS) 간 인터페이스 및 프로토콜을 정의

### CAMP, SCMS, IEEE 1609.2, 1609.2.1의 관계

| 구분 | 역할 | 서로 연결되는 지점 |
| --- | --- | --- |
| CAMP | 연구 협력체 | SCMS PoC 설계와 개념 정의의 배경 |
| SCMS | 인증서 발급 관리 인프라 | 단말에 인증서와 신뢰 정보를 제공 |
| IEEE 1609.2 | 메시지 보안 규격 | SCMS가 발급하는 인증서의 형식, 단말의 메시지 서명/검증 처리 |
| IEEE 1609.2.1 | 단말 인증서 관리 규격 | 단말이 SCMS에서 인증서를 공급받는 인터페이스와 프로토콜 |

- 단말 ↔ SCMS : 1609.2.1에 따라 인증서를 공급받고 관리
- 단말 ↔ 단말 : 1609.2 형식의 인증서로 메시지를 서명하고 검증
