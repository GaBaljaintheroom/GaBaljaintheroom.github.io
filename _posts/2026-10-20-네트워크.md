## 인터넷

- 인터넷(Internet)은 전 세계의 수많은 네트워크를 서로 연결한 **네트워크들의 네트워크(Inter-Network)**
- 1960년대 말 미국 국방부의 **ARPANET**에서 시작됨
  - 일부 경로가 끊겨도 다른 경로로 통신할 수 있도록 중앙 집중형이 아닌 **분산형 구조**로 설계됨
  - 회선을 점유하는 방식 대신 데이터를 잘게 나눠 보내는 **패킷 교환 방식**을 사용함
- 서로 다른 기종, 서로 다른 네트워크끼리도 통신할 수 있도록 **TCP/IP**를 표준 프로토콜로 채택하면서 지금의 인터넷으로 발전함
- 인터넷 위에서 동작하는 대표적인 서비스로 웹(WWW, HTTP), 이메일(SMTP), 파일 전송(FTP), DNS 등이 있음

## 이더넷

- 이더넷(Ethernet)은 **LAN(근거리 통신망)에서 가장 널리 쓰이는 유선 네트워크 기술**로, IEEE **802.3** 표준으로 정의됨
- OSI 7계층 중 **1계층(물리)과 2계층(데이터 링크)**의 규격을 함께 정의함
  - 1계층 : 케이블 종류(UTP, 광케이블), 커넥터(RJ-45), 전송 속도(10M/100M/1G/10Gbps...) 등
  - 2계층 : MAC 주소 체계, 이더넷 프레임 구조 등
- 초기 이더넷은 하나의 회선을 여러 단말이 공유했기 때문에 **CSMA/CD** 방식으로 충돌을 제어함
  - CS(Carrier Sense) : 회선이 사용 중인지 먼저 확인
  - MA(Multiple Access) : 회선이 비어 있으면 누구나 전송 가능
  - CD(Collision Detection) : 충돌이 감지되면 전송을 멈추고 랜덤 시간 후 재전송
- 이후 **스위치**가 보급되고 전이중(Full Duplex) 통신이 일반화되면서 충돌 자체가 거의 발생하지 않게 되었고, CSMA/CD는 사실상 사용되지 않음

**이더넷 프레임 구조**

| 프리앰블 | 목적지 MAC | 출발지 MAC | 타입 | 데이터 | FCS |
| --- | --- | --- | --- | --- | --- |
| 8 Byte | 6 Byte | 6 Byte | 2 Byte | 46 ~ 1500 Byte | 4 Byte |

- 타입(EtherType) : 상위 계층 프로토콜이 무엇인지 알려줌 (예: IPv4 = `0x0800`, ARP = `0x0806`, IPv6 = `0x86DD`)
- FCS(Frame Check Sequence) : 전송 중 데이터가 손상되었는지 확인하기 위한 값(CRC)

## 프로토콜

- 프로토콜(Protocol)은 **장치들이 서로 통신하기 위해 미리 정해둔 약속(규칙)**
  - 사람끼리도 같은 언어를 써야 대화가 되듯이, 장치끼리도 같은 프로토콜을 사용해야 통신할 수 있음
- 프로토콜은 크게 세 가지 요소로 구성됨
  - 구문(Syntax) : 데이터의 형식, 헤더 구조, 부호화 방식 등
  - 의미(Semantics) : 각 필드나 제어 정보가 어떤 의미인지
  - 타이밍(Timing) : 전송 속도, 순서 등 언제 어떻게 주고받을지
- 네트워크 프로토콜은 다음 두 측면으로 나눠 볼 수 있음
  - 물리적 측면 : 데이터 전송 매체, 신호 규약, 회선 규격 등. 이더넷이 널리 쓰임
  - 논리적 측면 : 장치들끼리 통신하기 위한 프로토콜 규격. TCP/IP가 널리 쓰임

## OSI 7 계층

- 국제표준화기구(ISO)에서 정의한 네트워크 참조 모델로, 네트워크 통신 과정을 **7개의 계층으로 나눠 표준화**한 것
- 계층을 나누는 이유
  - 통신 과정을 단계별로 나눠서 이해하기 쉬움
  - 문제가 생겼을 때 어느 계층에서 발생했는지 범위를 좁혀 **트러블슈팅이 쉬움**
  - 각 계층은 독립적이어서 한 계층의 기술이 바뀌어도 다른 계층에 영향을 주지 않음 (예: 유선 → 무선으로 바뀌어도 HTTP는 그대로 사용)
- OSI 7계층은 크게 두 부분으로 구분할 수 있음
  - **하위 4계층(1~4계층)** : 데이터를 잘 **전달**하는 데 집중하는 계층
  - **상위 3계층(5~7계층)** : 데이터를 잘 **만드는** 데 집중하는 계층 (애플리케이션 영역)

**OSI 7계층과 TCP/IP 4계층 비교**

| OSI 7계층 | TCP/IP 4계층 | 프로토콜 예시 | 데이터 단위(PDU) | 주요 장비 |
| --- | --- | --- | --- | --- |
| 7. 애플리케이션 | 애플리케이션 | HTTP, FTP, SMTP, DNS | 데이터 | - |
| 6. 프레젠테이션 | 애플리케이션 | JPEG, MPEG, SSL/TLS | 데이터 | - |
| 5. 세션 | 애플리케이션 | NetBIOS, RPC | 데이터 | - |
| 4. 트랜스포트 | 트랜스포트 | TCP, UDP | 세그먼트 | 로드 밸런서, 방화벽 |
| 3. 네트워크 | 인터넷 | IP, ICMP, ARP | 패킷 | 라우터 |
| 2. 데이터 링크 | 네트워크 액세스 | 이더넷, Wi-Fi | 프레임 | 스위치, NIC |
| 1. 피지컬 | 네트워크 액세스 | - | 비트 | 허브, 리피터, 케이블 |

- TCP/IP 모델은 4계층으로 구분함
  - 실제 인터넷에서 사용하는 모델로, OSI 7계층보다 단순하고 실용적임
  - OSI의 5~7계층을 **애플리케이션 계층** 하나로, 1~2계층을 **네트워크 액세스 계층** 하나로 묶음
  - 데이터를 만드는 애플리케이션 부분과 이 데이터를 잘 전달하는 데 집중하는 하부 계층으로 구분하는 것이 목적

### 1계층(피지컬 계층)

- 목적 : 0과 1의 디지털 데이터를 전기 신호(또는 광 신호, 무선 신호)로 변환해 **전기 신호를 잘 보내는 것**
- 주요 장비 : 허브, 리피터, 케이블, 커넥터, 트랜시버, 탭
  - 허브, 리피터 : 네트워크 통신을 중재하는 네트워크 장비
    - 리피터 : 약해진 신호를 증폭해 더 멀리 보낼 수 있게 해줌
    - 허브 : 여러 포트를 가진 리피터. 들어온 신호를 다른 모든 포트로 전달함
  - 케이블, 커넥터 : 케이블 본체를 구성하는 요소
  - 트랜시버 : 컴퓨터의 랜카드와 케이블을 연결하는 장비
  - 탭 : 네트워크 모니터링과 패킷 분석을 위해 전기 신호를 다른 장비로 복제해줌
- 1계층 장비는 주소의 개념이 없으므로 전기 신호가 들어온 포트를 제외하고 모든 포트에 같은 전기 신호를 전송함
  - 허브에 연결된 모든 단말이 하나의 충돌 도메인(Collision Domain)을 공유하게 되어, 단말이 많아질수록 충돌이 늘어나고 성능이 떨어짐

### 2계층(데이터 링크 계층)

- 목적 : 출발지와 도착지 주소를 확인하고 내게 보낸 것이 맞는지, 또는 내가 처리해야 하는지에 대해 검사한 후 데이터 처리를 수행
- 같은 네트워크(LAN) 안에서 **인접한 장비 간의 통신**을 담당함
- 주요 장비 : 네트워크 인터페이스 카드(NIC), 스위치
- MAC 주소를 이해할 수 있고 스위치는 MAC 주소를 보고 통신해야 할 포트를 지정해 내보냄
- FCS를 이용해 전송 중 발생한 **에러를 검출**함

**MAC 주소**

- 네트워크 인터페이스 카드에 부여된 **48비트(6바이트)의 물리적 주소** (예: `00:1A:2B:3C:4D:5E`)
  - 앞 24비트(OUI) : 제조사 식별 번호
  - 뒤 24비트 : 제조사가 각 장비에 부여한 고유 번호
- 제조 시 할당되는 고유한 주소이기 때문에 IP 주소처럼 네트워크 구조에 맞춰 계층적으로 관리할 수 없음 → 3계층의 논리 주소(IP)가 필요한 이유

**네트워크 인터페이스 동작 방식**

1. 전기 신호를 데이터 형태로 만든다.
2. 목적지 MAC 주소와 출발지 MAC 주소를 확인한다.
3. 네트워크 인터페이스 카드의 MAC 주소를 확인한다.
4. 목적지 MAC 주소와 네트워크 인터페이스 카드를 갖고 있는 MAC 주소가 맞으면 데이터를 처리하고 다르면 데이터를 폐기한다.

목적지 MAC 주소와 일치한다면 이 데이터를 상위 계층에서 처리할 수 있도록 메모리에 적재함

> 목적지가 브로드캐스트 주소(`FF:FF:FF:FF:FF:FF`)인 경우에는 내 MAC 주소가 아니더라도 데이터를 처리함
{: .prompt-tip }

**스위치의 동작 방식**

- 단말이 어떤 MAC 주소인지, 연결된 포트는 어느 것인지 주소 습득 과정에서 알 수 있음
  - 프레임이 들어오면 **출발지 MAC 주소와 들어온 포트**를 MAC 주소 테이블에 기록함 (Learning)
- 이 데이터를 기반으로 단말들이 통신할 때 포트를 적절히 필터링하고 정확한 포트로 포워딩해줌
  - 플러딩(Flooding) : 목적지 MAC 주소가 테이블에 없으면 들어온 포트를 제외한 모든 포트로 전송
  - 포워딩(Forwarding) : 목적지 MAC 주소가 테이블에 있으면 해당 포트로만 전송
  - 필터링(Filtering) : 목적지가 들어온 포트와 같은 쪽에 있으면 다른 포트로 전송하지 않음
  - 스위치의 적절한 필터링과 포워딩 기능으로 통신이 필요한 포트만 사용하고 네트워크 전체에 불필요한 처리가 감소하면서 이더넷 네트워크
    효율성이 크게 향상되었고 이더넷 기반 네트워크가 급증하는 계기가 되었음
- 스위치는 포트마다 충돌 도메인을 분리해주지만, 브로드캐스트는 모든 포트로 전달되므로 **브로드캐스트 도메인은 분리하지 못함**

### 3계층(네트워크 계층)

- 목적 : 서로 다른 네트워크 간에 **목적지까지 최적의 경로를 찾아 패킷을 전달**하는 것
- IP 주소와 같은 논리적인 주소가 정의됨
- MAC 주소와 달리 IP 주소는 사용자가 환경에 맞게 변경해 사용할 수 있고 네트워크 주소 정보를 이용해 자신이 속한 네트워크와 원격지 네트워크를 구분할 수 있고,
  원격지 네트워크를 가려면 어디로 가야 하는지 경로를 지정할 수 있음
  - IP 주소는 **네트워크 주소 + 호스트 주소**로 구성되고, 서브넷 마스크로 이 둘을 구분함 (예: `192.168.1.10/24`)
- 주요 장비 : 라우터
  - IP 주소를 사용해 최적의 경로를 찾아주고 해당 경로로 패킷을 전송하는 역할을 함
  - 라우팅 테이블을 참고해 패킷을 다음 홉(Next Hop)으로 전달함
  - 브로드캐스트를 다른 네트워크로 전달하지 않으므로 **브로드캐스트 도메인을 분리**함
- 주요 프로토콜
  - IP : 패킷의 주소 지정과 전달
  - ICMP : 네트워크 상태 확인과 에러 메시지 전달 (예: `ping`)
  - ARP : IP 주소로 MAC 주소를 알아냄 (2계층과 3계층을 이어주는 역할)

### 4계층(트랜스포트 계층)

- 패킷 네트워크는 데이터를 분할해 패킷에 실어보내다 보니 중간에 패킷이 유실되거나 순서가 바뀌는 경우가 생길 수 있음
- 패킷이 유실되거나 순서가 바뀌었을 때 바로잡아 주는 역할을 담당
  - 시퀀스 번호 : 데이터를 분할한 순서를 표시해 받는 쪽에서 순서대로 재조립할 수 있도록 함
  - ACK 번호 : 데이터를 잘 받았다는 응답. 응답이 오지 않으면 재전송함
- 포트 번호를 이용해 **하나의 단말 안에서 어떤 애플리케이션으로 데이터를 전달할지 구분**함
  - 3계층(IP)이 단말까지 데이터를 전달한다면, 4계층(포트)은 단말 안의 프로세스까지 전달함
  - 예: HTTP 80, HTTPS 443, SSH 22, DNS 53
- 대표 프로토콜

| 구분 | TCP | UDP |
| --- | --- | --- |
| 연결 방식 | 연결 지향 (3-way handshake) | 비연결형 |
| 신뢰성 | 순서 보장, 재전송, 흐름/혼잡 제어 | 보장하지 않음 |
| 속도 | 상대적으로 느림 | 빠름 |
| 사용 예 | HTTP, 이메일, 파일 전송 | DNS, 실시간 스트리밍, 게임 |

- 주요 장비 : 로드 밸런서, 방화벽
  - 애플리케이션 구분자(포트 번호)와 시퀀스, ACK 번호 정보를 이용해 부하를 분산하거나 보안 정책을 수립해 패킷을 통과, 차단하는 기능을 수행함

### 5계층(세션 계층)

- 양 끝단의 응용 프로세스가 연결을 성립하도록 도와주고 연결이 안정적으로 유지되도록 관리하고 작업 완료 후에는 이 연결을 끊는 역할을 함
- TCP/IP 세션을 만들고 없애는 책임을 짐
- 에러로 중단된 통신에 대한 에러 복구와 재전송도 수행함
  - 통신 중간중간 동기점(Checkpoint)을 두어, 오류가 발생하면 처음부터가 아니라 마지막 동기점부터 다시 전송할 수 있도록 함
- 통신 방식(단방향, 반이중, 전이중)을 결정함
- TCP/IP 모델에서는 별도 계층으로 존재하지 않고 애플리케이션 계층에 포함됨

### 6계층(프레젠테이션 계층)

- 표현 방식이 다른 애플리케이션이나 시스템 간의 통신을 돕기 위해 하나의 통일된 구문 형식으로 변환시키는 기능을 수행함
- 일종의 번역기나 변환기 역할을 수행하는 계층
- 주요 기능
  - 인코딩/디코딩 : 문자 코드 변환(ASCII, UTF-8 등), 데이터 직렬화
  - 압축 : 데이터 크기를 줄임 (JPEG, MPEG, GIF 등)
  - 암호화/복호화 : 데이터를 안전하게 전달 (SSL/TLS)
- 앞서 정리한 [ASN.1]({% post_url 2026-10-11-ASN.1 %})도 서로 다른 시스템 간에 데이터 구조를 통일된 형식으로 표현하기 위한 표기법으로, 프레젠테이션 계층에 해당함

### 7계층(애플리케이션 계층)

- 네트워크 소프트웨어의 UI부분이나 사용자 입출력 부분을 정의하는 것이 애플리케이션 계층의 역할
- 사용자와 가장 가까운 계층으로, 사용자가 네트워크 서비스에 접근할 수 있도록 해줌
- 대표 프로토콜
  - HTTP/HTTPS : 웹 서비스
  - FTP : 파일 전송
  - SMTP, POP3, IMAP : 이메일 송수신
  - DNS : 도메인 이름을 IP 주소로 변환
  - SSH, Telnet : 원격 접속

## 인캡슐레이션과 디캡슐레이션

![인디캡 이미지](/assets/img/posts/2026-10-20/img.jpeg)

현대 네트워크는 대부분 패킷 기반 네트워크

- 패킷 네트워크는 데이터를 패킷이라는 작은 단위로 쪼개 보내는데, 하나의 통신이 회선 전체를 점유하지 않고 동시에 여러 단말이 통신하도록 해줌
- 데이터를 패킷으로 쪼개고 네트워크를 이용해 목적지로 보내고 받는 쪽에서는 패킷을 다시 큰 데이터 형태로 결합해 사용함

**인캡슐레이션(Encapsulation) : 데이터를 보내는 과정**

- 상위 계층에서 하위 계층으로 내려가면서 각 계층의 **헤더를 덧붙이는** 과정
- 상위 계층의 데이터 전체(헤더 + 데이터)는 하위 계층 입장에서 그냥 하나의 데이터(페이로드)로 취급됨

1. 7~5계층 : 애플리케이션이 전송할 **데이터**를 만듦
2. 4계층 : TCP/UDP 헤더(출발지·목적지 포트, 시퀀스·ACK 번호 등)를 붙여 **세그먼트**를 만듦
3. 3계층 : IP 헤더(출발지·목적지 IP 주소 등)를 붙여 **패킷**을 만듦
4. 2계층 : 이더넷 헤더(출발지·목적지 MAC 주소 등)와 트레일러(FCS)를 붙여 **프레임**을 만듦
5. 1계층 : 프레임을 **비트(전기 신호)**로 변환해 전송함

**디캡슐레이션(Decapsulation) : 데이터를 받는 과정**

- 인캡슐레이션의 반대로, 하위 계층에서 상위 계층으로 올라가면서 각 계층의 **헤더를 확인하고 제거하는** 과정

1. 1계층 : 전기 신호를 비트로 변환함
2. 2계층 : 목적지 MAC 주소가 내 주소인지 확인하고, 타입 필드를 보고 상위 프로토콜(IP)로 전달함
3. 3계층 : 목적지 IP 주소가 내 주소인지 확인하고, 프로토콜 필드를 보고 상위 프로토콜(TCP/UDP)로 전달함
4. 4계층 : 목적지 포트 번호를 보고 해당 애플리케이션으로 전달함
5. 7~5계층 : 애플리케이션이 데이터를 처리함

**인캡슐레이션하는 과정에서 헤더에 넣는 두 가지 정보**

- 현재 계층에서 정의하는 정보
  - 2계층 : MAC 주소, 3계층 : IP 주소, 4계층 : 포트 번호, 시퀀스·ACK 번호
- 상위 프로토콜 지시자
  - 받는 쪽에서 디캡슐레이션할 때 다음에 어떤 상위 프로토콜로 데이터를 넘겨야 하는지 알 수 있도록 표시함

| 계층 | 상위 프로토콜 지시자 | 예시 |
| --- | --- | --- |
| 2계층 (이더넷) | 이더타입(EtherType) | IPv4 `0x0800`, ARP `0x0806`, IPv6 `0x86DD` |
| 3계층 (IP) | 프로토콜 번호 | ICMP `1`, TCP `6`, UDP `17` |
| 4계층 (TCP/UDP) | 포트 번호 | HTTP `80`, HTTPS `443`, DNS `53` |
